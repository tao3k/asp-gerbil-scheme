** Authoritative entrypoints

- =gerbil.pkg= owns package identity and dependency acquisition.
- Root =build.ss= owns the complete library Graph through ASP PackageSpec and
  =std/build-script#defbuild-script=.
- =provider-package-spec.ss= owns the explicit provider runtime and executable
  BuildSpec; =build-provider.ss= passes it to
  =std/build-script#defbuild-script=.
- =std/make= owns compilation, import dependencies, currentness, parallel
  scheduling, artifact roots, clean, and native build flags.

** PackageSpec surface

=asp-gerbil-scheme-package-spec!= hygienically declares an ordinary POO object.
The normal library declaration needs only a =spec= binding. Module discovery
defaults internally to ASP's lightweight native catalog; callers supply
=(modules ...)= only for a real specialized Graph. The explicit
=(product-entry-modules ...)= option removes the declared product-owned closure
when projecting the native library spec. The root declaration includes the
provider entrypoints and executable runtime-state modules. Static operation
contracts and registry/command projections remain library-owned and have no
dependency on runtime dispatch; otherwise command discovery would implicitly
load the resident server implementation.

There is no public =roots=, source catalog DSL, development/production profile,
or alternate native plan format. =exclude-dirs= is retained as a POO-native
extension of the native ignore set. =native-spec= remains an advanced escape hatch
for a genuine native =std/make= BuildSpec such as the provider executable.

** Native defaults

Gxpkg evaluates =build.ss= from the package directory. ASP's default catalog excludes
=main.ss=, =manifest.ss=, scripts, =run/=, =t/=, =.git/=, =_darcs/=, and
=.gerbil/=. This repository adds no =exclude-dirs= overlay. The ignored
=build/workspace-provider/= tree was an artifact of the retired custom
=GERBIL_PATH= route, not a native source or output root.

The package does not rewrite =GERBIL_PATH=. Plain =gxi= may leave it unset and
fall back to =gerbil-home=; =gxpkg env= normally selects the package-local
=.gerbil= domain. =std/make= reads =gerbil.pkg= at the supplied package root and
derives the package output prefix itself.

=gxpkg build -R= and native =--release= requests remain upstream release mode.
Optimized and debug modes are forwarded by upstream entrypoints. ASP defines no
development or production mode.

** Cold bootstrap

Root =build.ss= source-imports only
=src/build-api/source-bootstrap.ss=. That internal module exposes the minimum
POO PackageSpec declaration bindings and is not re-exported by
=:asp-gerbil-scheme/building-api=. This lets a dependency-only environment compile
the whole package with zero installed ASP artifacts.

The provider declaration is independently source-importable and
=build-provider.ss= imports upstream =defbuild-script= directly. It does not
load the full public facade and does not rebind the caller artifact domain.

** Test Graph

=t/= is excluded from the production library Graph by the upstream native
default. GxTest discovers its own selected closure. When compiled execution is
required, the testing layer gives the explicit =src/...= and =t/...= module
paths to one =std/make= invocation at the package root. It does not construct a
package BuildPlan or reuse a production source-root option.

Native compile/spec/clean are available only through =build.ss=. The installed
project CLI retains test targets and no longer duplicates those commands.

Package projection observability is a =NativeProfile= POO slot.  A caller may
compose an observer, enable predicate, and heartbeat interval without wrapping
or replacing native execution.  Runtime heap limits belong to per-test Testing
profiles; package compilation remains wholly owned by =std/make=.

** Generated sidecars

A verified generated artifact may add immutable =extra-inputs:= to its matching
native =gxc:= item. It may not remove the target, predict target currentness, or
split the Graph. =std/make= still receives and owns the complete native spec.

** Required absence

The following former owners are intentionally removed:

- package development/production profile modules;
- custom build-script bridge and body;
- source-discovery and artifact-cleanup owners;
- =native-build.ss= and =native-build-spec.ss=;
- =package-native-plan.ss= and its hand-maintained stage list;
- package =project-build.ss= compile/spec/clean facade;
- ASP leases, lock recovery, scheduler mutation, currentness admission, and
  toolchain environment rewriting;
- the former =src/building= stage/request/runner framework and its build-time
  memory supervisor.

** Verification

Acceptance requires dependency-only cold library and provider builds, focused
package/GxTest tests, the canonical full test gate, exact-head CI on Linux and
macOS, and downstream =poo-flow= validation after pinning the green commit.
