** Boundary

Production package compilation is native Gerbil:

- =build.ss= declares the complete library Graph with
  =clan/building#init-build-environment!=.
- =build-provider.ss= declares the explicit provider executable Graph with
  =std/build-script#defbuild-script=.
- =std/make= alone owns import dependency resolution, currentness, build modes,
  compiler scheduling, workers, artifact locations, and clean behavior.
- =gerbil.pkg= owns package identity and dependency acquisition.

=src/building/= is an optional POO/functional value library for modelling
stages, requests, scenario fixtures, and observations. It is not on the
production package execution path and cannot suppress or partition a
=std/make= invocation.

** Root declaration

The library entry keeps the dependency-aware upstream declaration:

#+begin_src scheme
(import (only-in :clan/building
                 all-gerbil-modules
                 init-build-environment!)
        (only-in "./src/build-api/source-bootstrap"
                 asp-gerbil-scheme-package-spec!
                 asp-gerbil-scheme-library-package-prototype))

(asp-gerbil-scheme-package-spec!
 (library-package @ asp-gerbil-scheme-library-package-prototype)
 (spec library-spec)
 (modules (all-gerbil-modules))
 (product-entry-modules +product-entry-modules+))

(init-build-environment!
 name: "asp-gerbil-scheme"
 deps: '("clan" "clan/poo")
 spec: library-spec)
#+end_src

=PackageSpec='s =exclude-dirs= slot starts with clan's native exclusions for
=t/=, =run/=, =.git/=, =_darcs/=, and =.gerbil/=. A downstream POO declaration
may extend that inherited set for a real project source layout. This project
adds no overlay: the retired =build/workspace-provider= tree belonged to the
deleted custom =GERBIL_PATH= route and is not part of the native layout.

A downstream extension keeps the composed value in the same declarative object:

#+begin_src scheme
(asp-gerbil-scheme-package-spec!
 (downstream-package @ asp-gerbil-scheme-library-package-prototype)
 (spec downstream-spec)
 (exclude-dirs => append '("generated"))
 (modules (all-gerbil-modules exclude-dirs: exclude-dirs)))
#+end_src
=product-entry-modules= removes the complete product-owned module set from the
library projection inside PackageSpec. The declaration includes only the
provider executable and executable runtime-state owners. Static operation
contracts, registry projection, and command adapters remain library modules;
they do not import runtime dispatch. Removing only the executable entry file
would still be insufficient because =std/make= correctly follows imports.

There is no public =roots= option, development/production profile, alternate
module catalog, BuildPlan cache, ASP currentness predicate, build lease, or
toolchain mutation. =exclude-dirs= remains the POO-native extension point for
clan's ignore set.

A downstream package that requires build-process anomaly supervision composes
the public =call-with-framework-native-build-memory-anomaly-guard= around its
=init-build-environment!= call.  The wrapper observes the same positive caller
override or host CPU count as PackageSpec, but only PackageSpec mutates the
compiler capacity immediately before =std/make= settings are constructed.  The
guard therefore reports and supervises native concurrency without becoming a
second scheduler or forcing downstream code to copy capacity selection.

** Testing boundary

=gerbil test= and =:clan/testing= own test selection, discovery, loading,
execution, and reporting. Test compilation follows their native Gerbil path;
ASP does not pass a private closure through a second build adapter. Optional
POO profiles describe memory, performance, debug-trace, or shared-resource
instrumentation without becoming another runner.

** Optional Building values

The public Building value library retains =BuildStage=, =BuildRequest=, and
POO constructors where they support scenario composition and inspection. These
values are not package profiles and do not lower =gxpkg= build modes.
Release, optimized, and debug modes remain native Gerbil command options.

** Acceptance

The native boundary requires all of the following evidence:

1. a dependency-only cold =build.ss compile= succeeds with zero pre-existing
   ASP artifacts;
2. =build.ss spec= excludes =t/=, generated build trees, and product
   entrypoints;
3. the provider cold build and executable test succeed independently;
4. focused package/GxTest contracts pass;
5. the canonical full test gate passes;
6. CI library and provider jobs are green on Linux and macOS.
