** Finding

The upstream stack already owns the complete testing lifecycle. The
=gerbil-poo= package demonstrates the minimal =unit-tests.ss= entry:
=:clan/testing= initializes the test environment and imports the package
version module. Current Gerbil exposes the same lifecycle through
=gerbil test=.

The prior ASP framework duplicated discovery, selection, execution, report,
receipt, and build responsibilities. Those owners are retired. The stable ASP
surface now exports only POO instrumentation profiles and small observation
helpers.

** Current contract

| Concern | Owner |
|---------+-------|
| test arguments and recursive directories | =gerbil test= |
| suite loading, setup/cleanup, filtering, summary | =:clan/testing= |
| package/module graph | =clan/building= and =std/make= |
| memory/performance/debug/resource declaration | ASP POO profiles |
| POO method tracing | =:clan/poo/debug= |

** Audit gates

- focused extension tests execute through =gerbil test=;
- public Build API contains no retired framework owner;
- a clean =gerbil build= compiles only the current extension modules;
- policy scope derives from the upstream module graph;
- repository tests contain no runtime dependency on the retired runner.
