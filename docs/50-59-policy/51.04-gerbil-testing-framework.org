** Authority boundary

=gerbil test= and =:clan/testing= are the only test framework. They own recursive
discovery, suite loading, setup/cleanup, execution, progress, and summaries.
ASP does not provide a second runner, catalog, scope collector, report format,
or test DSL. Its discovery extension may only remove paths from the file list
already returned by clan; it never adds or independently discovers tests.

The ordinary package entry is the upstream form:

#+begin_src scheme
#!/usr/bin/env gxi
(import :gerbil/expander :clan/testing)
(init-test-environment!)
(import-module ':sample/version #t #t)
#+end_src

The native CLI remains:

#+begin_src shell
gerbil test t/example-test.ss
gerbil test -r example t/...
#+end_src

** POO profile extension

ASP adds immutable POO values that describe instrumentation around an upstream
test. Default profiles cover managed-heap observation, benchmark receipts,
=:clan/poo/debug= tracing, and shared-resource serialization. A project may
replace a profile with =.cc=, bind it to one test with =.map=, or remove it
with =.remove=.

#+begin_src scheme
(import :clan/poo/object
        :asp-gerbil-scheme/build-api)

(def +tests+
  (testing-interface-map-profile
   +asp-testing-interface+
   "t/large-graph-test.ss"
   (.cc +testing-memory-profile+ maxHeapMiB: 2048)))

(def +without-trace+
  (testing-interface-remove-profile +tests+ 'debug-trace))

(def +without-child-package-tests+
  (testing-interface-add-profile
   +tests+
   (.cc +testing-discovery-profile+
        ignoreDirectories: '("lambda-episteme"))))
#+end_src

The declaration is data, not another command-line language. Runtime adapters
may project these values into process limits and observations before the
upstream test process is loaded, but they may not rediscover tests or replace
=gerbil test=.

For a package-level negative discovery boundary, initialize the same clan
environment through the profiled entrypoint:

#+begin_src scheme
(init-profiled-test-environment! +without-child-package-tests+)
#+end_src

This entrypoint calls =clan/testing#find-test-files= first and filters only the
declared directories. The clan =test= entrypoint still imports and runs every
remaining suite. It also applies the selected runtime Profile before clan loads
those suites, so downstream entrypoints do not repeat heap setup.

** Source scope

Production scope comes from =clan/building#all-gerbil-modules=, which is the
same std/make graph used by the package build. Policy tests obtain their
=t/=-rooted modules through that same upstream graph and filter the explicit
=-test.ss= module set. ASP does not walk the repository or expand imports to
manufacture a second source graph.

** Acceptance

- the extension and every profile are native POO objects;
- per-test overrides are immutable and do not mutate defaults;
- removing a profile also removes its per-test bindings;
- upstream =gerbil test= executes focused tests directly;
- a clean native package build succeeds without any retired runner module.
